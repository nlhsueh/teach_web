#### 複製現有專案 (`main`)

為了方便解說，我們直接使用之前完成的專案當作範例。直接從之前的專案複製 (clone) 下來執行。

1. **STEP1: 複製專案 (Clone)**
```bash
git clone https://github.com/nlhsueh/nlh_tennis_club.git
cd nlh_tennis_club
```

2. **STEP2: 建立並啟動虛擬環境**

如果你的電腦已經有虛擬環境，可以略過此步驟。

```bash
# 建立環境
py -m venv venv101

# 啟動環境 (Windows)
venv101\Scripts\activate
# 啟動環境 (Mac/Linux)
source venv/bin/activate
```

> ps.如果有成功，前面會多出 `(venv101)` 的標誌，或是用 which python 來檢查，如果顯示的路徑中有 `venv101`，就表示成功了。


3. **STEP3: 安裝必要套件**
如果你的虛擬環境已經安裝過這些套件，可以跳過此步驟。否則請執行以下指令：

```bash
pip install -r requirements.txt
```

其中 `requirements.txt` 是一個文字檔，裡面列出專案需要的套件和版本。例如：

```text
# 核心網頁框架
Django==6.0.8

# 影像處理套件 (使用 Django ImageField 時必備)
Pillow==12.0.0
```

**若沒有 `requirements.txt`**，請使用以下指令單獨安裝（注意：版本號非必要，省略即可）：
```bash
pip install django pillow
```

4. **STEP4: 啟動伺服器**
```bash
python manage.py runserver
```

`nick_tennis_club` 一開始是空的，輸入 `http://127.0.0.1:8000` 會看到一個預設的火箭發射的歡迎頁面。

這些是 Django 預設安裝的應用程式（apps），它們提供了一系列常用的功能 and 服務，以協助開發 Web 應用程式。以下簡述一下每個應用程式的作用：

1. `django.contrib.admin`: 提供一個自動生成管理介面的框架，讓開發者可以輕鬆地管理網站的後台資料，包括用戶、群組、資料庫內容等。
2. `django.contrib.auth`: 提供用戶身份驗證和權限管理的功能，包括用戶登錄、登出、註冊、密碼重置等功能，並且支持多種身份驗證方式。
3. `django.contrib.contenttypes`: 提供了內容類型框架，用於管理 and 追蹤 Django 模型的內容類型，使得模型之間可以建立通用的關聯關係。
4. `django.contrib.sessions`: 提供用於處理用戶 Session 的框架，使得開發者可以在 Web 應用程式中存儲和管理用戶的 Session 數據，以實現用戶會話跟踪等功能。
5. `django.contrib.messages`: 提供用於在 Web 應用程式中顯示消息的框架，包括成功、錯誤、警告等不同類型的消息，用於向用戶提供操作結果反饋。
6. `django.contrib.staticfiles`: 提供靜態文件處理的功能，包括收集靜態文件、提供靜態文件的 URL、管理靜態文件的版本等，用於管理和服務靜態資源（如 CSS、JavaScript 文件）。

#### lab2.3 設定網址路由

* 當我們打 `127.0.0.1:8000/xxx` 時，會透過網址路由來對應到相對的回應模組 (views)
* django 中，網址路由直接由 `urlpatterns` 來設定, 寫 in `urls.py` 中。
* **專案路由** 的 `urlpatterns` 放在專案下，主要設定admin 的路徑和其他子系統的路徑。
* **子系統路由** 設定路徑與回應模組的關係，放在該子系統的 `urls.py` 下。

專案路由：加上第五行的設定

> my_tennis_club/my_tennis_club/urls.py:

```python
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path('', include('members.urls')),
    path('admin/', admin.site.urls),
]
```

子系統路由：

> my_tennis_club/members/urls.py: 

**注意**：此 `urls.py` 須自己建立
```python
from django.urls import path
from . import views

urlpatterns = [
    path('', views.members, name='members'),
    path('members/', views.members, name='members'),
]
```

#### 1. Model

* Model 是設計資料的地方，每一個資料表用一個 class 來宣告設計:
    * 必須繼承 `models.Model`
* 每個資料欄位有不同的型態，常見的如
    * 字串 (`CharField`), 
    * 整數 (`IntegerField`), 
    * 日期 (`DateField`),
* 不同型態的資料有不同的參數設定，例如 `Charfield` 需要設定最大長度
* `__str__()` 用來設計該資料被要求顯示時，該如何顯示


```python
from django.db import models

class Member(models.Model):
  firstname = models.CharField(max_length=255)
  lastname = models.CharField(max_length=255)

  def __str__(self):
    return f"{self.firstname} {self.lastname}" 
```

#### 2. Migration

當我們對資料庫的格式進行了變更，就必須告知系統，有兩步驟：
1. 產生資料遷移檔 (makemigration)
2. 執行遷移 (migrate)

```shell
python manage.py makemigrations
python manage.py migrate
```

#### 4. 修改視界回應

```python
from django.http import HttpResponse
from django.template import loader
from .models import Member

def members(request):
    mymembers = Member.objects.all().values()
    template = loader.get_template('all_members.html')
    context = {
        'mymembers': mymembers,
    }
    return HttpResponse(template.render(context, request))
```
* `context` 使用 `dict` 的結構封裝參數
* `template` 透過 `.render` 把參數 and 請求送到網頁 

#### 讀取與呈現資料


```html
<!DOCTYPE html>
<html>
<body>

<h1>Members</h1>
  
<ul>
  {% for x in mymembers %}
    <li>{{ x.firstname }} {{ x.lastname }}</li>
  {% endfor %}
</ul>

</body>
</html>
```
* 樣板變數 (template variable)
    * `{{ var }}`
* 樣板標籤 (template tag)
    * `{% for %}`, `{% endfor %}`
    * see [all template tag](https://docs.djangoproject.com/en/5.0/ref/templates/builtins/)

1️⃣ 關於 Python 的虛擬環境（Virtual Environment, venv），下列敘述何者**錯誤**？
- (A) 它可以為不同的專案隔離各自獨立的 Python 執行環境與第三方套件，避免套件版本衝突。
- (B) 在 macOS/Linux 中建立好名為 `venv` 的虛擬環境後，可以使用 `source venv/bin/activate` 來啟用它。
- (C) 啟動虛擬環境後，使用 `pip install` 安裝的套件會被安裝在系統全域環境中，讓電腦上的所有使用者都能共用。
- (D) 在 Windows 命令提示字元（CMD）中，啟用虛擬環境的指令為 `venv\Scripts\activate`。

<details>
<summary>解答</summary>
(C)。  
說明：啟動虛擬環境後，使用 `pip` 安裝的任何套件都會被限制並安裝在該虛擬環境專屬的資料夾中，不會影響到系統全域的 Python 環境，這也是虛擬環境用來實現專案依賴隔離的核心目的。
</details>

2️⃣ 若要在已啟用的虛擬環境中安裝 Django，並建立一個名為 `my_tennis_club` 的全新 Django 專案骨架，最正確的指令組合順序為下列何者？
- (A) `pip install django` ➔ `django-admin startproject my_tennis_club`
- (B) `pip install django` ➔ `python manage.py startproject my_tennis_club`
- (C) `npm install django` ➔ `django-admin startproject my_tennis_club`
- (D) `pip install django` ➔ `django-admin startapp my_tennis_club`

<details>
<summary>解答</summary>
(A)。  
說明：在 Python 中，我們使用包管理器 `pip install django` 安裝 Django 套件。安裝成功後，系統會提供 `django-admin` 工具，此時可執行 `django-admin startproject <project_name>` 來初始化並建立全新的專案目錄與設定。在專案尚未建立之前，是沒有 `manage.py` 檔案的，因此無法使用 `python manage.py` 指令。
</details>

3️⃣ 在 Django 中，要建立一個名為 `members` 的子系統（應用程式 App），應該使用哪一個指令？
- (A) `django-admin startproject members`
- (B) `python manage.py startapp members`
- (C) `python manage.py startproject members`
- (D) `django-admin startapp members`

<details>
<summary>解答</summary>
(B)。  
說明：在 Django 中，`django-admin startproject` 用於建立全新專案，而建立子系統（App）則必須在專案目錄下使用 `python manage.py startapp <app_name>` 指令。
</details>

4️⃣ 關於 Django 的 MVT 設計模式，下列敘述何者**錯誤**？
- (A) M 代表 Model，負責處理與資料庫相關的資料結構與邏輯。
- (B) V 代表 View，負責處理網頁的邏輯、商務邏輯與決定呈現什麼資料。
- (C) T 代表 Template，負責控制資料在資料庫中的儲存格式。
- (D) Django 的 MVT 在本質上與傳統的 MVC（Model-View-Controller）架構非常相似。

<details>
<summary>解答</summary>
(C)。  
說明：T 代表 Template，負責前端頁面的呈現與外觀排版（HTML 樣板），而非資料庫中的儲存格式（資料庫中的儲存格式是由 Model 負責）。
</details>

5️⃣ 【簡答題】在 Django 專案中，當我們修改了 App 中的 `models.py` 後，必須執行哪兩個步驟才能將變更正式套用到資料庫中？請簡述這兩個步驟的指令與目的。

<details>
<summary>解答</summary>
(無)。  
說明：當修改了 `models.py` 後，必須執行以下兩個步驟：
1. **產生資料遷移檔**：執行 `python manage.py makemigrations`，這會根據 Model 的修改在 App 下的 `migrations` 目錄中生成遷移記錄檔。
2. **執行遷移**：執行 `python manage.py migrate`，這會將剛才生成的遷移檔內容實際套用到資料庫（例如 SQLite）中，更新資料表的欄位或結構。
</details>
